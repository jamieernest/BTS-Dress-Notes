# Follow-up UX review

This review covers the combined follow-up in PR54 above PR30: sticky composition preferences, navigation and people filters, note references, agreements, mentions, chat replies and layout, show tags, and website profile photos. It evaluates the rehearsal workflow: find a note, write quickly, identify a person and get back to the show. It is an expert inspection with synthetic browser checks, not an end-user usability study.

The review uses [Nielsen’s ten usability heuristics](https://www.nngroup.com/articles/ten-usability-heuristics/). [Apple’s design principles](https://developer.apple.com/design/human-interface-guidelines/design-principles/) inform clarity, agency and consistency; [Linear’s interface review](https://linear.app/now/behind-the-latest-design-refresh) informs restrained hierarchy and familiar controls. These are evaluation references, not a requirement to imitate either product’s appearance.

Agreement count and pressed state show the result of a toggle on both notes and their comments. |

Reply cancellation, reversible agreements and retained drafts support backing out. Unsaved tag edits survive incoming updates, including a useful Dismiss state if another window removes that tag. |

## Specific browser evidence

Shitposts now has one notification badge: pending mentions show `@`; otherwise it shows the unread-message count. The button's accessible name retains both known counts. Mentions use the existing blue accent treatment and take priority over the quieter ordinary count. Opening a visible chat clears both states; messages arriving while the document is hidden remain unread until the person returns to the open chat. Reset clears both indicators.

The navigation/settings review used the running synthetic preview at 390×844 and 1280×800. These checks did not modify live venue data or submit settings changes to the shared preview server.

- Plain person suggestion → Tab creates the named author filter. With that filter active, choosing another person and explicitly selecting Mentions preserves both filters. Each person chip contains its dropdown and a quiet clear icon inside one boundary; clearing it preserves other active filters. Plain names and @-prefixed names use the same person lookup; @ alone offers up to eight known accounts.
- The same two person filters survive loading a saved show by URL. The “Notes mentioning you” search option appears only for bare `@`, after the authenticated account is known; empty focus stays closed and `@Alex` offers matching people. Selecting it uses the normal “Mentions you” chip without reopening the menu. Arbitrary recipients retain their own names. Entering `38` and accepting “Note #38” yields the exact `#38` result, retaining the saved-show identifier and other filters.
- Search close icon, Escape, and Ctrl+A followed by Backspace immediately clear text search and its URL parameter while retaining person filters. Focus returns to search. There is no search-mode panel or keyboard footer.
- No horizontal overflow was observed in the inspected main, saved-show and Settings views at 390px.
- Settings initially disables every unchanged Save. Its colour controls measure 44×44px at the mobile width. Tags used by notes show a disabled Delete and a plain explanation.
- A synthetic incoming tag update, delivered locally to the Settings handler without a server mutation, preserved two unsaved names and updated a third untouched name. A mocked successful save of `Crew ` normalised to `Crew` and left Save disabled. An edit made during a pending request survived its acknowledgement and remained saveable.
- The final combined `npm test` run passed all **266 tests**, including the latest search and comment-agreement changes. Syntax and diff checks were clean. The integrated desktop main-page smoke check confirmed the assembled behaviour after the separate feature checks. Comment agreements update in place without replacing the parent note DOM, preserving its other controls and focus.

## Remaining limits

Viewport checks do not reproduce a physical phone keyboard, touch hardware or every assistive technology. The new behaviour has not been tested with representative nontechnical rehearsal users; this review cannot establish that every interaction is easy for them. Existing storage-dependent preferences can be unavailable when a browser disables storage. Website photo identity assumes its username matches the OIDC username; a missing image or claim falls back to initials rather than guessing from an editable email alias.
